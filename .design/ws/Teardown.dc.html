WHY IT BITES HARDEST
The terminal status is the last message emitted, so it is the one most likely to still be queued at teardown — and it is what drives _persist_status → run_status. Reconciliation is startup-only by design, so a finished run reads as still running until the app restarts.
WHAT IS NOT AFFECTED
Durability, entirely. sink.append_message runs synchronously on the calling thread before the live hand-off, so every dropped message is already in the buffer and on its way to Delta. Cancel is unaffected too — it rides the socket, not the pump.
